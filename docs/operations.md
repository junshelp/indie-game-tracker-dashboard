# 운영과 복구

## 발행 순서

1. 출처 수집과 큐레이션을 마치고 전체 캘린더를 확정합니다.
2. 최신 캘린더로 행사 JSON을 만듭니다. Drive 업로드 직후에는 같은 로컬 파일을 `--no-drive --calendar-file`로 전달해 읽기 지연을 피합니다.
3. Steam 데이터를 수집합니다.
4. `validate_dashboard.py`로 날짜·상태·URL·집계·스냅샷을 검증합니다.
5. `push_dashboard.py`의 격리 dry-run으로 diff를 확인하고 발행합니다.
6. 원격 커밋과 Pages 배포 결과를 확인합니다.

캘린더 편집·Drive 업로드·Slack 보고는 개인 Hermes 스킬에서 관리합니다. 스킬의 실행 스크립트는 이 저장소의 `scripts/`와 같은 버전으로 유지합니다.

## 상태와 실패

기본 영속 경로는 `~/.hermes/state/indie-game-event-tracker/`입니다. `events/`와 `steam/`에는 마지막 발행 성공 스냅샷과 이력을 저장합니다. 생성 중인 결과는 여기에 덮어쓰지 않습니다. `publish/`는 배포 전용 checkout이며 개발 작업에 사용하지 않습니다. `publish.lock`은 동시 배포를 막습니다.

이전 성공 데이터가 없을 때만 `--baseline-dir`로 마지막 배포 데이터를 지정합니다. 최초 적재는 baseline으로 처리합니다. 기존 행사 누락이 있으면 기본적으로 빌드를 중단합니다. 의도한 삭제를 검토한 경우에만 `--allow-removals`를 사용합니다.

날짜 파싱·검증 실패, 불완전한 캘린더, 인증 실패 시 원격 데이터와 마지막 성공 스냅샷을 유지합니다. 일부 일정으로 재구성한 자료를 전체 데이터처럼 발행하지 않습니다. HTTP 403/429만으로 행사를 삭제하지 않습니다.

## UI 변경

기본 배포는 데이터와 캐시 버전만 갱신합니다. UI는 저장소에서 수정·검증·커밋합니다. 배포 스크립트를 통한 UI 복사는 `--include-ui --ui-dir /explicit/source`를 지정했을 때만 실행하며 CSS도 포함합니다. `/tmp`의 오래된 UI를 자동으로 복사하지 않습니다.

`--dry-run`은 별도 임시 clone에서만 파일 복사·버전 증가·stage를 하고 제거합니다. 원격, 영속 state, 실운영 checkout은 변경하지 않습니다. 일반 발행도 미커밋 변경이 있는 checkout을 덮어쓰지 않습니다.

## 되돌리기

잘못된 배포는 `git revert <commit>`으로 되돌리고 검증 후 정상 push합니다. baseline은 마지막으로 확인한 원격 `data/`에서 복구합니다. 영속 state가 원격보다 앞서거나 다른 버전이면 먼저 백업하고 일치시킵니다.
